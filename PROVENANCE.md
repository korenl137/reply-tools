Disable reply-comment and code-copy when you install this one, or the reply is drawn twice.

What it does, version 0.1.0:

- Fullscreen terminal, reply drawn by the engine: the reply is redrawn paragraph by paragraph (as reply-comment did) with a dim ❝ in a fixed gutter that appends `> quote` and `comment: ` to the prompt draft; a fenced block also gets ⧉ in the same gutter (one row per block, not a second button row). A reply another mod drew keeps that drawing, with one ❝ over it.
- One dim row under a reply (only when it has two or more blocks or any command): `⧉ copy [command]… [reply text]` (0.1.2: `[reply md]` dropped for the built-in `/copy`), the first four, then `[+N more]` / `[fewer]`. Inline code spans that read as commands (a `! ` or `$ ` prompt, or a known command word and an argument) get a button; fenced blocks are listed there too when another mod drew the reply.
- Copy strips a leading `! `, `$ ` or `% ` (shell blocks with prompts keep only the typed commands, as code-copy did; `!` is new). `# ` is not stripped: it is also a comment. "reply text" is the reply with markdown marks removed.
- `/quote`: a pane of the last five replies (`[older]`/`[newer]` by click), paragraphs toggled with ☐/☑ (digit keys 1-9 toggle the first nine rows while the prompt is empty), `[split into sentences]` per paragraph, a note field, Enter fills the prompt. `/quote sel` quotes the last mouse selection.
- One parser (`hooks/blocks.ts`) serves both quote and copy. Changes from reply-comment's paragraph rule: a fence right after a line of text is its own block.
- Nothing submits a prompt; failures toast instead of passing silently (reply-comment's press handlers could fail without a word).
